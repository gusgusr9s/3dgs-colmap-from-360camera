## 3. ตรวจ training mask ก่อน/หลัง optimization

ยังใช้ LRASPP MobileNetV3 weights เดิม, class person 15, transform เดิม, threshold 0.05, close 21×21, dilate 15×15 และ fill-lower-components เดิม

การเปลี่ยนใน `7d2a2a5` คือทำ decode/encode และ postprocess ขนานกัน, batch GPU จาก 4 เป็น 8 และเพิ่ม CUDA postprocess แต่ **งานจริงบนเครื่องนี้ใช้ DirectML inference + CPU postprocess**

รันทดสอบแบบอ่านอย่างเดียว 12 ภาพจาก `8cc360d5d3` ครอบคลุมเฟรม 0, 900, 1800, 3000, 4200 และมุมแนวนอน/เงย:

- ใช้ probability เดียวกันผ่านสูตร OpenCV เดิมและสูตรปัจจุบัน: ต่างกัน **0 พิกเซลทั้ง 12 ภาพ**
- คำนวณ CPU inference ปัจจุบันแล้วเทียบ mask DirectML ที่บันทึกไว้: ต่างกัน **0 พิกเซลทั้ง 12 ภาพ**
- mask เดิมจาก Ultra 1536 กับ High 1024 เมื่อเทียบขนาดเดียวกันต่าง 0.057–1.313% ต่อภาพ และ High มีบริเวณถูก mask มากกว่าเล็กน้อยในทุกภาพตัวอย่าง
- ตรวจภาพใน training_input จริง: mask ครบ 6576/6576 (`8cc`), 2176/2176 (`a465`), 2912/2912 (`e738` ทุก 15), 18384/18384 (`d366`); เป็น hardlinks ของ mask ใน brush_data ทุกภาพที่ตรวจ ไม่มีไฟล์ mask หาย

ผลนี้ครอบคลุมภาพตัวอย่างและ backend ที่ใช้งานจริง ยังไม่พิสูจน์ recall ของคนทุกคนในวิดีโอหรือความเท่ากันบน CUDA ทุกเครื่อง เปอร์เซ็นต์พื้นที่ถูก mask รวมพื้น/rig และ false positives จึงใช้แทนอัตราลบคนสำเร็จไม่ได้

## 6. การทดลองเพื่อแยกสาเหตุถัดไป

1. ใช้ source เดียว ช่วงเดียว profile/ขนาดภาพเดียว sample ทุก 10 ตาม default ที่เลือก และ split/masks เดียวกัน ใช้มากกว่า 240 ตำแหน่งเพื่อให้ครอบคลุมเงื่อนไขที่เปิด staged mapping; ที่ 30 FPS/ทุก 10 เฟรมต้องยาวกว่าประมาณ 80 วินาที การทดสอบชั่วคราว 5–10 วินาทีไม่ครอบคลุมเส้นทางนี้
2. คัดลอก feature/matching database ชุดเดียวกันไปยัง workspace แยก แล้วหา pose ใหม่ 3 แบบ: **A balanced + staged**, **B balanced + staged off**, **C full + staged off** เทียบ A/B เพื่อแยกผลของ staged mapping และ B/C เพื่อแยกผลของ balanced/full ใช้ matcher และ person masks ก่อนหา pose ชุดเดียวกันทั้งหมด และไม่ reuse completed poses
3. เทียบ High กับ Ultra โดยตรึง pose/เฟรม และวัด render มุมเดียวกัน เพื่อวัดผลรวมของ preset ด้านความละเอียด/งบ train หากต้องการหาผลเฉพาะความละเอียด ให้ตรึง steps และ max splats เพิ่มด้วย
4. เมื่อตรวจผลการเว้นเฟรม ให้ใช้ preset และวิธีหา pose เดียวกันทั้งทุก 4/10 เฟรม พร้อมกำหนดตำแหน่งทดสอบร่วมกันก่อนเริ่ม train
5. ระบุคนที่หลุดจาก mask เป็นรายภาพ แล้วเทียบ detector/ความละเอียด inference บนตัวอย่างนั้น การลด threshold อย่างเดียวอาจลบต้นไม้และฉากเพิ่ม

การตรวจครั้งนี้สร้างเฉพาะไฟล์รายงานและภาพในโฟลเดอร์ review ไม่แก้ config, code, dataset, model หรือ server ที่ใช้งานอยู่

## 8. ตรวจความน่าเชื่อถือของรายงานซ้ำ

### ใช้ภาพอ้างอิงที่ขนาด 1024 เท่ากัน

การวัดข้อ 7 ต้องขยาย High 1024 ไป 1536 จึงตรวจความไวต่อ reference/resize เพิ่ม โดยใช้ภาพต้นทาง High 1024 เป็น reference, ย่อ Ultra ด้วย `INTER_AREA`, คง High ที่ขนาดเดิม และใช้พื้นที่ valid ร่วมกันใน mask ทั้งสองรุ่น:

| วิธีรวมคะแนน | Ultra ทุก 4 เฟรม | High ทุก 10 เฟรม |
|---|---:|---:|
| ค่าเฉลี่ย PSNR รายมุม — 1296 มุม | 26.2627 dB | 25.3234 dB |
| PSNR จาก error รวมทุก valid pixel — 1296 มุม | 25.3859 dB | 24.6343 dB |
| ค่าเฉลี่ย PSNR รายมุม — แนวนอน 648 มุม | 25.0017 dB | 24.2502 dB |

ความต่างเฉลี่ยรายมุมยังประมาณ 0.94 dB และ Ultra สูงกว่าใน 1113/1296 มุม ทิศทางของผลจึงคงเดิมเมื่อเปลี่ยน reference และวิธี resize ในการตรวจนี้ แต่ตัวเลขยังวัดภาพ render และยังมีตัวแปรที่เปลี่ยนพร้อมกันตามข้อ 7

ตรวจ source fingerprint, frame_index, yaw และ pitch ตรงกันครบทุกภาพ ไม่มีชื่อภาพซ้ำ และตำแหน่ง train/eval ไม่ทับกัน: Ultra train 1149 ตำแหน่ง, High train 411 ตำแหน่ง, eval ร่วมกัน 81 ตำแหน่ง ทั้งนี้ COLMAP ใช้ภาพทั้งหมดในการหา pose ตาม pipeline เดิม การกันไว้ทดสอบเป็นการกันออกจากขั้น Gaussian training

### ตรวจทิศกล้องเพิ่มเติม

ผลเดิมใน `trajectory_comparison.json` ตรวจเฉพาะตำแหน่งกล้อง จึงเพิ่มการเทียบทิศกล้องจาก camera-to-world rotation หลังจัดสองแผนที่ด้วย similarity transform เดียวกัน บน 246 ตำแหน่งร่วมกัน:

- ความต่างทิศกล้อง median **0.162°**, p95 **0.246°**, สูงสุด **0.362°**
- ความต่างตำแหน่ง median **0.295%** ของ RMS รัศมีเส้นทาง Ultra

ผลแสดงว่าตำแหน่งและทิศกล้องของสองรุ่นสอดคล้องกันโดยรวม การเปรียบเทียบกับผลประมาณรุ่นก่อนยังไม่ใช่ ground truth และความต่างเล็กน้อยอาจมีผลต่อรายละเอียดภาพ จึงยังใช้ตัดความเป็นไปได้ของ pose error หรือพิสูจน์ว่า staged mapping แม่นเท่า full ไม่ได้

### ขอบเขตของข้อสรุป mask

ผล 0 พิกเซลต่างกันตรวจความเท่ากันของสูตร postprocess และความสอดคล้องกับ mask ที่บันทึกไว้ใน **12 ภาพตัวอย่าง** ไม่ได้วัด precision/recall ของคนทุกคน และค่า masked PSNR ตั้งใจไม่นับบริเวณคนที่ถูก mask จึงไม่ใช้คะแนนนี้ยืนยันว่า model ลบคนดีขึ้นหรือแย่ลง

ไฟล์ตรวจซ้ำ: `common_1024_audit.json`, `check_common_resolution.py` และ `pose_orientation_audit.json`

## หลักฐานเพิ่มเติม

- `model_history.json`: config/quality และ flags จากงานจริง
- `constant_comparison.json`: เทียบ defaults และ QUALITY_PROFILES ด้วย Python AST
- `mask_comparison.json`: จำนวนพิกเซลต่างกันรายภาพ
- `trajectory_comparison.json`: ความสอดคล้องของตำแหน่งที่ตรงกันหลัง similarity alignment
- `compare_masks.py`: ขั้นตอนทดสอบที่รันซ้ำได้
