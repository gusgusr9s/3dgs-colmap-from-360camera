# ตัวอย่างสำหรับเดินในโมเดล

เลือกข้อมูลที่กล้องย้ายตำแหน่งผ่านพื้นที่จริง เดินไป–กลับหรือวนผ่านหลายทาง และกลับมาเชื่อมบริเวณเดิม ภาพ 360 จากจุดเดียวเห็นทุกทิศ แต่ไม่ได้เห็นพื้นผิวที่ถูกบังเมื่อย้ายไปตำแหน่งใหม่ จึงยังเบลอหรือเป็นรูได้เมื่อเดินออกจากบริเวณที่ถ่าย

## 360Loc Concourse — เดินวนกลับจุดเริ่ม ภาพ 6K

- แหล่งต้นทาง: [360Loc / ผู้เผยแพร่](https://github.com/HuajianUP/360Loc), [หน้าโครงการ](https://huajianup.github.io/research/360Loc/), [paper CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Huang_360Loc_A_Dataset_and_Benchmark_for_Omnidirectional_Visual_Localization_with_CVPR_2024_paper.pdf)
- ชุด `mapping/daytime_360_1`: ภาพจริง 6144×3072 จำนวน 491 ตำแหน่ง พร้อม poses จากผู้เผยแพร่
- คำนวณจาก poses ที่แจก: ระยะเส้นทางรวมประมาณ 230.0 เมตร, พื้นที่ครอบคลุมตามแกน X/Y ประมาณ 90.7×51.7 เมตร, จุดเริ่ม/จุดจบห่างกันประมาณ 0.3 เมตร เป็นเส้นทางเดินยาวแล้ววนกลับผ่านอีกด้าน
- ตัวอย่างในเครื่องเลือกทุก 2 ตำแหน่ง ได้ **246 ภาพ** ครอบคลุมเส้นทางเดิมทั้งหมด ระยะห่างมัธยฐานประมาณ 0.95 เมตร เก็บภาพ JPEG ต้นฉบับโดยไม่ลดขนาด และตรวจ ZIP CRC ทุกไฟล์
- รูปต้นฉบับ: `data/raw/360loc_concourse_walk_stride2/images/frame_*.jpg`
- ข้อมูลจับคู่รูปกับชื่อเดิม/พิกัด: `data/raw/360loc_concourse_walk_stride2/frames.json`; poses เดิม: `published_poses.txt`
- `360loc_concourse_walk_stride2.mkv` รวม JPEG ต้นฉบับโดยคัดลอก packets ไม่ re-encode ใช้เป็น input ในหน้า Sources ได้ ภาพมีการเคลื่อนที่ระหว่างเฟรมจริง แต่ **2 fps เป็นความเร็วเปิดดูที่กำหนดขึ้น ไม่ใช่ FPS หรือความยาววิดีโอต้นฉบับ**
- หากมี `360loc_concourse_walk_preview_2k.mp4` ให้ใช้เปิดดูในเว็บเท่านั้น เป็นสำเนาย่อจากภาพต้นฉบับ; สำหรับเทรนรายละเอียดใช้ MKV 6K หรือภาพ JPEG ต้นฉบับ

ดาวน์โหลดซ้ำ หรือเก็บครบ 491 ตำแหน่ง:

```powershell
.\.venv-win\Scripts\python.exe scripts/download_walking_sample.py --stride 2
# เก็บต้นฉบับครบทุกตำแหน่ง (ประมาณ 1 GB เฉพาะรูป)
.\.venv-win\Scripts\python.exe scripts/download_walking_sample.py --stride 1
```

แนะนำเลือก Panorama / Ultra, FOV 90°, มุมละ 1536×1536, sample every 1 เพื่อใช้ทุกรูปใน sequence ที่เลือกไว้ เริ่มช่วงต่อเนื่อง 20–30 ตำแหน่งเพื่อตรวจ pose ก่อนขยายทั้งเส้นทาง

เป็นทางเดินและโถงขนาดใหญ่ มีคนเคลื่อนที่ กระจก และคนถือกล้องอยู่ด้านล่าง ควรใช้ masks ที่ pipeline มีอยู่ คุณภาพโมเดลต้องตรวจจากภาพเรนเดอร์หลังเทรน

สำหรับชุด stride 2 นี้ มีสคริปต์นำเข้า poses จากผู้เผยแพร่และจุดเริ่มต้นจาก depth ให้เว็บแอปใช้แทนการหา poses ใหม่ด้วย COLMAP:

1. สร้าง Views จาก MKV 6K ด้วยค่าข้างต้นและปิด Auto model ให้ได้ครบ 246 ตำแหน่ง / 3,936 มุม
2. นำ job ID จากหน้าเว็บมาใส่ในคำสั่งต่อไปนี้ (ต้องเป็น job ใหม่ที่ยังไม่มี `brush_data`):

   ```powershell
   .\.venv-win\Scripts\python.exe scripts/prepare_360loc_model.py --job JOB_ID
   ```

3. เมื่อสคริปต์แจ้ง READY เปิด Camera Preview แล้วกด Generate 3D ที่ job เดิม เว็บแอปจะใช้ poses ที่ตรวจไว้และเก็บข้อมูลเทรนของแต่ละรุ่นแยกกัน

สคริปต์ตรวจ JSON poses เทียบกับ TXT ทุกตำแหน่ง ตรวจ CRC ของ depth และทดสอบสเกล depth กับ poses เมตริกบนสามคู่ภาพที่ห่างกันประมาณ 5–8 เมตร โดยสเกลที่ตรงกันคือ 0.01 เมตรต่อค่าที่เก็บหนึ่งหน่วย (ตรวจจากข้อมูล ไม่ใช่หน่วยที่มีเอกสารรับรอง) แล้วสร้าง person/operator masks, สุ่มจุดจาก depth ทุก 8 ตำแหน่งและรวมจุดใน voxel 5 ซม. สำหรับเริ่มเทรน Gaussian ภาพเทรนยังใช้ครบทุกตำแหน่ง ไม่ได้ลดเหลือเฉพาะเฟรม depth

เว็บแอปยังไม่มีปุ่ม import poses ภายนอกทั่วไป สคริปต์นี้เจาะจง source และลำดับภาพของ Concourse stride 2 เพื่อป้องกันใช้ตำแหน่งกล้องผิดชุด

ผลที่สร้างในเครื่องวันที่ 8 ต.ค. 2026: job `2e88b6a8dc`, โมเดล `web_data/models/2e88b6a8dc_20261008_224910_02a4c5a7.ply` ขนาด 944 MB, Gaussian 4 ล้านจุด, Ultra 30,000 รอบ ใช้ครบ 246 ตำแหน่ง / 3,936 มุม เส้นทางจากตำแหน่งที่เลือกยาว 229.2 เมตร ตรวจ held-out renders 232 ภาพได้ masked PSNR เฉลี่ย 23.00 dB ตรวจภาพต้น/กลาง/ปลายทางและมุมที่คะแนนต่ำแล้ว โครงสร้างหลักต่อกัน แต่กระจกและบริเวณคนเดินบางส่วนยังฟุ้ง

เมื่อเปิดเว็บแอปพอร์ต 8000: [เปิดโมเดล Concourse](http://127.0.0.1:8000/model/2e88b6a8dc_20261008_224910_02a4c5a7.ply) เลือกจุดถ่ายทั้ง 246 ตำแหน่ง หรือกด Walk เพื่อเดินด้วย WASD ความเร็วเริ่มต้น 1.4 เมตร/วินาที ปรับความสูงทีละ 1 ซม. และใช้ Free view เพื่อเคลื่อนขึ้น/ลงได้ โมเดลนี้เป็น artifact ในเครื่องและไม่ได้เพิ่มไฟล์ใหญ่เข้า Git

หน้าผู้เผยแพร่ไม่ระบุ license เผยแพร่ไฟล์ภาพแยกชัดเจน จึงเก็บรูป/MKV/MP4 เป็นตัวอย่างในเครื่องและไม่เพิ่มไฟล์ใหญ่เข้า Git

## AIST Living Lab — วิดีโอเดินในอาคาร 2 นาที 16 วินาที

`aist_living_lab_1.mp4`, 1920×960, 29.97 fps, 136.00 วินาที ดูได้ในหน้า Sources

ตรวจภาพที่หลายช่วงตั้งแต่ 0–120 วินาที: กล้องเดินผ่านทางเดิน เลี้ยวเข้าพื้นที่ข้าง ๆ และกลับผ่านโถง/ทางเดินที่เห็นก่อนหน้า เหมาะทดสอบหลายตำแหน่งกว่าคลิปหมุนอยู่บริเวณเล็ก แต่ความละเอียดน้อยกว่าชุด 360Loc

สร้างโมเดลช่วง **0–45 วินาที** แล้ววันที่ 9 ต.ค. 2026: เก็บทุก 8 เฟรม,
169 ตำแหน่ง/2,704 ภาพ 448×448, หา spherical COLMAP poses ใหม่ได้ครบ 169/169
ตำแหน่ง ไม่พบช่วงเส้นทางกระโดด, reprojection error เฉลี่ย 0.72 px
ใช้ person/operator masks และกรอง sparse seed แล้วเทรน High 20,000 steps
ได้ 989,351 Gaussians, masked held-out PSNR เฉลี่ย 27.97 dB จาก 160 มุม
ตรวจภาพต้น/กลาง/ปลายทางแล้ว ทางเดินและห้องต่อกัน; บางส่วนใกล้กระจก/แสงจ้ายังนุ่ม
สเกลของโมเดลนี้เป็น relative ไม่ได้วัดระยะเดินเป็นเมตร และยังไม่ได้เทรนทั้งคลิป 136 วินาที

## ชุดภาพทางเดินอีกตัวเลือก

[Indoor3Dmapping](https://zenodo.org/records/6367381): 99 ภาพ panorama 1920×960 พร้อม positions และ depth, CC BY 4.0 สภาพฉากเป็นทางเดินเชื่อมห้องในอาคาร ใกล้เคียงตัวอย่าง Corridor

ตรวจไฟล์ positions แล้วพบว่าระยะบางคู่ห่างกันหลายเมตร จึงไม่ควรถือว่าทุกคู่ห่าง 1 เมตรตามคำอธิบายหน้าเว็บเสมอ ควรแบ่งบริเวณที่ต่อเนื่องหรือใช้ poses/depth ที่แจก ชุดนี้ยังไม่ได้เตรียมครบเป็น input สำหรับเว็บแอป

สำหรับถ่ายเอง ควรเดินเชื่อมทางเดินและห้อง ถ่ายทั้งขาไป/ขากลับ เดินวนรอบวัตถุที่อยากดูใกล้ ๆ และกลับมาทับบริเวณเดิม ช่วงทางเลี้ยว/ประตูให้ถ่ายถี่ขึ้น เพื่อให้การจับคู่ภาพต่อกันได้ ดูค่าความคมเพิ่มเติมใน `QUALITY_GUIDE.md`
